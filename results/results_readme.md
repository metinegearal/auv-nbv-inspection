# Mid-Run Evaluation Results

This directory contains the files produced by the NBV planner and benchmark logger.

## Main chart

`benchmark_trajectory_overview.png` is an XY overview of the mission:

- **Solid dark line:** the vehicle's measured trajectory. The benchmark logger samples the current odometry position every 0.5 seconds.
- **Dashed lines:** future trajectories generated by the planner. Each dashed line is one planned trajectory from one planning iteration. These are not measured vehicle motion.
- **Colored points:** NBV viewpoint candidates. Their color represents the `utility` score. Candidate positions and target positions are stored in `planner_nbv_iterations.jsonl`.
- **Orange wedges:** the camera pose associated with each depth frame. The wedge direction uses the recorded yaw; the full roll, pitch, and yaw are available in `planner_depth_poses.csv`.
- **Blue rectangle:** the configured rectangular object from `(-14.1, -81.1)` to `(-12.0, -82.7)`.
- **Brown lines:** the two configured pipe centerlines. They are a simplified 2D representation of the cylindrical objects.
- **Small numbers:** a candidate waypoint's 1-based trajectory ID when it was selected into a published future trajectory. An unlabeled candidate was not selected into a published route.
- **Green point:** first measured vehicle position.
- **Red point:** latest measured vehicle position.

The plot is generated when the mission finishes. It can also be regenerated with:

```bash
ros2 run benchmark_evaluator plot_benchmark_results --results-dir results
```

## Files

- `benchmark_trajectory.csv`: measured vehicle trajectory sampled by the benchmark logger.
- `benchmark_depth_poses.csv`, `benchmark_nbv_iterations.jsonl`, and `benchmark_future_trajectories.csv`: initialized benchmark-prefix telemetry files; the populated mid-run planner records use the corresponding `planner_*` files below.
- `trajectory_benchmark_<timestamp>.csv`: legacy copy of the measured trajectory.
- `planner_trajectory.csv`: reserved planner telemetry trajectory file; the main measured path is `benchmark_trajectory.csv`.
- `planner_nbv_iterations.jsonl`: one JSON record per planning iteration. It includes iteration timing, whether a route was published, whether the previous route was blocked, and every candidate's cluster, position, target, utility, raw gain, raw cost, and `trajectory_id`.
- `planner_future_trajectories.csv`: every waypoint of every future trajectory published by the planner, grouped by `iteration`.
- `planner_depth_poses.csv`: vehicle position and roll, pitch, and yaw matched to each depth frame.
- `evaluation_parameters.txt`: planner processing time and OctoMap leaf count for each planning cycle.
- `optuna_mission_stats.txt`: final mission time, distance, average speed, and trajectory sample count.
- `final_map_ros2.bt`: final OctoMap, when the planner uses its default map path.

The generic telemetry CSV and JSONL files are reset when a new logger node starts. Timestamped legacy benchmark CSV files are retained.

## Changing the camera cone shape

Edit the `Wedge` call in `src/benchmark_evaluator/benchmark_evaluator/midrun_logger.py`:

```python
Wedge((x, y), 0.45, yaw - 25, yaw + 25, ...)
```

- Change `0.45` to change the cone radius in plot units/meters.
- Change both `25` values to change the half-angle. For example, `yaw - 40, yaw + 40` makes a wider cone.
- Change `alpha=0.12` to make the cone more or less transparent.
- Change `facecolor` and `edgecolor` to change its colors.

The plotted cone is a 2D XY representation using yaw. Pitch and roll are still preserved in `planner_depth_poses.csv`, but cannot be shown as a true 3D cone in this 2D chart.
