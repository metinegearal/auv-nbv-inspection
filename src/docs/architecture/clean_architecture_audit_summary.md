# Clean Architecture Global System Audit

Read [Phase 1: current and target topology, metric definitions and tables](phase_1_topology.md) first. Then follow the seven package reports below. Scope is `NBV_paper_ros2/src`; all paths in findings are relative to that directory. This is an analysis-only snapshot dated 2026-10-05. No application source or configuration was modified.

## 1. Executive Summary

The system has recognizable ROS deployment components but no explicit policy-owned abstract interfaces. Policy and framework/IO code coexist inside major nodes and mapper classes. The most consequential dependency is production planning/auv_stereo_depth importing a concrete logger from the experiment component, whose optimizer depends back on application launch/configuration.

- **Overall System Distance from Main Sequence:** mean D = **0.702381**, population variance D = **0.090986**, over seven packages under the explicitly imputed zero-denominator convention. These are unweighted package statistics, not defect probabilities or class-weighted scores.
- **Mathematically defined subset:** mean D = **0.750000**, population variance D = **0.050000**, n=5. Excludes isolated auv_inspection_planner (undefined I) and class-free auv_bringup (undefined A). An unqualified seven-package mean is mathematically undefined without a convention.
- **44 indexed findings:** 7 Critical, 34 Moderate, 3 Low. Several rows describe facets of the same architectural cause; this is not a count of independent defects.
- **Three elementary deployment-component cycles**, one increasing-I edge, and **no detected import-only inter-package cycle**. All 37 locally defined production classes/structs are non-abstract under the stated counting rule. Framework subclasses and mixin-like helpers are not counted as explicit interfaces.
- **Hotspots:** auv_benchmark (shared concrete dependency plus reverse orchestration); auv_planner_reference.NBVUtilityNode (mission/mapping/IO in one node); auv_inspection_planner.RealTimeStereoMapper (mapping/planning/storage in one class); auv_motion_control.WaypointControlNode (guidance/platform allocation/ROS); auv_stereo_depth.compute_depth (import-time model/device/file initialization).

The package metrics are deliberately a closed seven-component view. Concrete outer adapters such as auv_sim_bridge can look maximally painful in that view despite having appropriate framework dependencies. Do not rank remediation by D alone or add abstractions to stable value objects just to lower D. Positive boundaries already exist: pure route/collision/continuity functions, separate C++ search helpers, simulator factory injection and an NBV timing callback.

## 3. Circular Dependencies (ADP Violations)

Observed edges include imports, executable package-name references and direct cross-package configuration access. The exact elementary cycles, modulo starting point, are:

1. `auv_benchmark → auv_bringup → auv_benchmark`.
2. `auv_benchmark → auv_bringup → auv_stereo_depth → auv_benchmark`.
3. `auv_benchmark → auv_bringup → auv_planner_reference → auv_benchmark`.

The strongly connected component is `{auv_benchmark, auv_bringup, auv_stereo_depth, auv_planner_reference}`. `auv_motion_control` and `auv_sim_bridge` are outgoing sinks; `auv_inspection_planner` is isolated in this scoped component graph. See the [edge evidence table](phase_1_topology.md#current-inter-package-dependency-graph).

The import-only and scoped manifest-only graph is acyclic. Cyclic ROS command/observation flow is not evidence of ADP. The optimizer is not started by the default launch; its reverse launch dependency still belongs to the shipped component's source/deployment responsibilities. The SDP violation is `auv_benchmark (I=0.250) → auv_bringup (I=0.833)`. No external-library SDP claim is made because those libraries' incoming clients were not audited.

## 5. Target Migration Roadmap (Analysis Only)

The current graph is cyclic, so a global dependency-depth order does not exist until the experiment/telemetry SCC is broken. Work inside that SCC first. Establish contract/domain leaves before moving policy; then attach concrete leaf adapters to those contracts. Do not begin by replacing the simulator or motor behavior.

| Order | Component boundary and dependency rationale | Reviewable completion criterion for a future refactor |
|---|---|---|
| 1 | Define policy-owned value contracts and narrow telemetry/map/control ports. These become inward graph leaves; retain ROS array conversion at adapters. | Pose, trajectory, calibration, occupancy and event semantics are explicit; policy contract modules import no ROS, Torch, OctoMap or file IO. |
| 2 | Separate MidrunLogger/file sinks from evaluation and extract the optimizer into an outer experiment component. Rewire planner/auv_stereo_depth to client-owned telemetry ports. | Recompute the component graph: all three current cycles disappear; auv_bringup does not depend on experiment orchestration; installed component manifests describe actual edges. |
| 3 | Move class-independent domain routines first: route/collision rules, continuity costs, coordinate transforms and metric functions. Their limited dependencies make them inexpensive foundation leaves. | Existing numerical behavior and collision rejection cases remain characterized; no ROS startup or model import required. |
| 4 | Extract Python mission use cases from NBVUtilityNode; introduce map read/write/snapshot and trajectory-output adapters. Split preprocessing and solver invocation from selection/acceptance policy. | Use cases run against in-memory map/output/clock implementations; stale-pose reconnection, blacklisting, cancellation, float32 boundary checks and collision acceptance remain specified. |
| 5 | Extract C++ mapper responsibilities behind matching semantic contracts; retain its separate algorithm variant until behavior differences are measured. | Map backend replacement does not modify candidate/route policy; search and smoothing can be invoked outside ROS. |
| 6 | Split depth policy from model initialization and ROS synchronization; package model assets and isolate research/dataset utilities. | Importing depth policy performs no checkpoint/GPU/file initialization; runtime supplies estimator, calibration and timing sink explicitly. |
| 7 | Extract waypoint queue and control law, leaving platform mixing and command publication in adapters. Separate simulator sensor conversion, stepping, current-field policy and configuration loading. | Existing command semantics are characterized before changes; controller policy accepts values and substitutes output/mixer; bridge startup no longer executes a mission in its constructor. |
| 8 | Consolidate evaluation/reporting adapters and version TrialResult/configuration contracts; reconcile all seven manifests and classify legacy paths for separate release or later retirement. | Each reusable component declares its dependency closure; report wording changes do not break experiment result parsing. |

Steps 4–7 can proceed independently once shared contract ownership and SCC removal are settled. Do not migrate by deleting old paths before comparing the active Python, alternative C++ and legacy behavior. No deletion, build-system change, test alteration, controller change or implementation refactor is authorized by this audit.

## 6. Coverage, Evidence Quality and Limits

- [Source coverage and dependency/symbol inventory](source_coverage.md) records all 92 scoped text source/build/configuration files, including all 74 source/script files, tests, empty package markers, dormant code and vendored BGNet. Binary weights, images, bytecode, dataset filename lists and Markdown are not executable source and do not enter class metrics.
- Python ASTs were parsed without importing application modules; source imports, class definitions, functions, local call relationships and explicit IO/framework calls were inspected. C++ definitions/includes, build inputs, contracts and algorithm/node call sites were inspected statically; no compiler-resolved whole-program call graph is claimed. Filesystem checks and SHA-256 snapshots verify the audit did not alter these inputs.
- Functional tests, ROS nodes, GPU inference, simulator and optimizer were not run. Executing them is unnecessary for documentation generation and could create runtime artifacts or start missions.
